# 龙脉 · A股主线龙头雷达

一个移动端优先的 Vue 3 H5，用来把"先定主线，再选个股"拆成可检查的数据闸门：主线是否连续、梯队是否完整、资金是否连续两天流入。并在盘后把主线、催化、历史龙头画像合成隔夜条件单，在盘前 9:15–9:30 用集合竞价数据做最后复核。行情来自公开网页接口，不接券商、不自动下单，只做观察与复盘。

> 先说清楚：GitHub 上不存在经过长期实盘验证、可以稳定"高准确率抓龙头"的开源项目，也没有可公开复现的"竞价高胜率模型"。本项目参考的是数据工程与量化研究的通用做法（见文末），选股口径来自你给出的口诀，并尽量把"数据不足"如实暴露出来，而不是编造胜率。

## 快速开始

要求 Node.js 16 及以上（本项目在 16.20.2 上构建通过）。

```bash
npm install
npm run dev:all      # API :8787 + Vite :5173，开发时打开 http://127.0.0.1:5173
```

生产模式（单端口，由 Node 直接托管构建产物）：

```bash
npm run build
npm start            # http://127.0.0.1:8787
```

如果 npm 走了本机代理并报 `ECONNREFUSED 127.0.0.1:7897`：

```bash
npm --proxy=null --https-proxy=null install --registry=https://registry.npmmirror.com
```

API 端口可通过环境变量修改：`PORT=9000 npm start`。

如果本机已有旧版本进程占着 8787，而新页面打开竞价 / 隔夜出现 404，说明前端已是新版、后端还是旧进程。请另起端口验证：

```bash
PORT=8793 npm start   # 打开 http://127.0.0.1:8793
```

本次验收使用 `8795`；如果它也被占用，可用 `PORT=8800 npm start`。旧的 `8787 / 8788` 进程没有竞价 / 隔夜 / 画像接口，`8793` 有接口但没有最新的资金兜底和上证指数，都不要用它们判断新版功能。新版前端一旦发现后端缺少新字段，会在页面顶部显示"当前连接的是旧后端"，并给出 `8795` 入口；竞价等接口 404 时也会直接提示正确地址。

## 页面

- **主线**：上证指数实时条（含当日分时折线、昨收基准、红绿分时量、较昨日同期量能对比与沪深两市涨跌家数）、今日决策闸门、情绪五维评分、连续两日主线候选、新起题材（仅观察）、退潮掉队方向、三关口径说明。
- **选票**：按角色筛选的观察池；实时价格 1 秒刷新，涨停标的显示实时封单金额与占流通比例，开板立即提示；点开单票可看分时结构、关键数据、角色定位、数据证据与风险纪律。
- **竞价**：三个子页签。
  - **竞价抓强**：9:15–9:30 每 1.5 秒刷新，按 9:15 试撮 / 9:20 锁单 / 9:25 定稿 / 9:30 承接分阶段；非竞价时段只展示下一场准备池，不伪造竞价分。
  - **隔夜计划**：收盘后生成条件单草稿，列出触发、失效、止损、仓位和跳空区间；只在三关通过且情绪修复 / 主升时给出"可制定"，催化必须人工核验后才显示"可挂条件单"。
  - **老龙画像**：回溯板块内 3 板以上领涨股的次日延续率与隔夜跳空，按六个维度分桶统计，并随本机使用逐日累积样本。
- **复盘**：昨日涨停今日溢价、首板/连板晋级率、连板天梯、涨停板块分布、炸板与跌停池、自动复盘结论。
- **战法**：完整口诀、标准化盘后 / 盘前 / 开盘流程、四道闸门、竞价五条硬规则、隔夜六条硬规则、三种龙头角色、老龙画像口径、"准确率"验证方法、公开评分公式、数据来源与本工具"不做什么"。

## 接口

所有接口均为本机 Node 服务提供，默认端口 `8787`：

| 接口 | 说明 |
| --- | --- |
| `GET /api/dashboard?refresh=1` | 聚合看板：上证指数、情绪、板块三关、梯队、选票、复盘、数据降级项 |
| `GET /api/quotes?secids=0.002156,1.600410` | 批量实时报价（最多 80 只，支持 `1.000001` 上证指数）；`seal=1` 时附带腾讯五档买一、`sealed` 与 `sealFund`（涨停封单金额） |
| `GET /api/trend?secid=0.002156` | 单票 / 板块分时；`compare=1` 时附带较上一有效交易日同期量能对比；上证指数（`1.000001`）额外返回 `breadth`（沪深两市涨跌家数）与 `marketCompare`（沪深两市合计成交额对比） |
| `GET /api/auction` | 盘前竞价：阶段、候选、试撮 / 锁单 / 定稿、观察池 |
| `GET /api/overnight` | 盘后隔夜计划：状态闸门、条件单、观察、未过三关板块 |
| `GET /api/dragon-profile?days=30&refresh=1` | 老龙头画像：样本统计、六维分桶、最近样本；首次可能返回 `building:true`，前端每 4 秒重试 |
| `GET /api/health` | 服务状态、看板年龄、画像摘要 |

`/api/dragon-profile` 的 HTTP 响应会剥离 `rawSamples` 原始样本明细；完整样本只保留在本机 `.cache/dragon-profile.json`，避免把整份历史明细发到前端。

## 数据来源

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 涨停池 / 炸板池 / 跌停池 | 东方财富 `push2ex` | 涨停家数、连板数、首封时间、封单、炸板次数、行业板块 |
| 个股实时报价 | 腾讯 `qt.gtimg.cn` 批量行情 | 1 秒级价格、涨跌幅、换手、流通市值、五档买一价 / 买一量、涨停封单金额；选票页带 `seal=1` 时以腾讯价校准现价，避免东财备用节点的深市滞后价 |
| 上证指数 | 东方财富 `push2` 批量行情（`1.000001`），失败切 `push2test`；分时走 `trends2`；沪深两市成交额与昨日同期用腾讯指数行情 / 多日分时 | 首页点位、涨跌幅、沪市成交额、今开 / 最高 / 最低、涨跌家数、当日分时折线与逐分钟红绿成交量、沪深两市成交额及较昨日同一时点的放量 / 缩量结论（含今日总额、差额金额与百分比） |
| 板块当日主力资金 | 东方财富 `push2`，失败自动切 `push2test` 同源节点 | 今日板块主力净流入 |
| 板块历史资金 | 东方财富 `push2his`，失败自动切 `push2test` 同源节点 | 连续 2 日 / 5 日资金判断 |
| 历史日线 | 腾讯 `web.ifzq.gtimg.cn` 前复权日线 | 老龙头样本的次日延续率、隔夜跳空 |
| 集合竞价报价 | 腾讯批量行情 + 东方财富涨停池 | 9:15–9:30 竞价涨幅、竞价额、板块共振 |
| 板块目录 | 东方财富 `push2/push2test` 实时目录，失败退回本地 `server/data/boards.json` | 行业板块与资金接口映射 |
| 题材催化 | 人工核验，仅存本机 localStorage | 政策 / 产业 / 事件 / 传闻 / 暂无 |
| 老龙头样本累积 | 本机 `.cache/dragon-profile.json` | 跨交易日累积，上限 120 日 / 600 条 |

这些都不是官方开放 API，可能限流、改字段或临时不可用。程序的处理原则是：

1. 单次失败不阻塞整页，成功的数据继续展示；当日资金与历史资金分开计失败次数，单只板块异常不会连坐整轮；
2. 只有关键字段确实没有替代数据时，页面顶部才出现"数据源部分降级"提示，并列出失败项；
3. 资金缺失时闸门显示未通过，选票统一降级为"仅观察"，不会用 0 或假数据补齐；
4. 当日 / 历史资金各自连续失败 3 次才进入 60 秒冷却；历史缓存 10 分钟、当日资金缓存 20 秒；
5. `push2 / push2his` 连接被重置时自动切换同源 `push2test` 节点，并记住主节点故障 2 分钟，期间直接走备用节点，避免反复白等；
6. 当日明细失败时优先回退到板块列表里的真实 `f62`，昨日资金优先回退到本机快照；两者都有时不再误报降级；
7. 本机 `.cache/flow-daily.json` 会记录每次成功读到的板块当日资金，作为第二天"连续流入"的本地快照。

## 核心算法

### 1. 三关定主线

一个板块必须同时通过以下三项，才算"三关通过"：

1. **连续两日靠前**：今日与昨日涨停家数都 ≥ 2，且今日排名 ≤ 8、昨日排名 ≤ 10。
2. **梯队完整**：板块内同时存在高位连板（≥ 3 板）、中位二板、低位首板。
3. **资金连续流入**：今日与昨日板块主力均为净流入。只有今日流入、昨日数据缺失时，如果 5 日累计为正，会显示金色"≈ 近似"标记供参考，但**不会**让板块通过资金关，也不会解除"仅观察"状态。

任何一关不过，都不会给出可执行结论。没有板块通过三关时，顶部直接显示"空仓等待"，个股分数被限制在观察区间。

首页主线候选按「三关通过数 → 热度 → 连板高度」排序，强度第一的方向单独置顶，其余方向默认收起，避免卡片堆叠。情绪分只描述环境温度，不解除三关限制：情绪高但没有板块过三关，仍然只观察核心、不追高。

催化是单独的人工核验项：板块标记政策 / 产业 / 事件且三关通过后，个股才按"综合分"展示；未标记或标为"暂无催化"的，一律显示「待催化」并压成观察分；标为"纯传闻"的方向会直接从选票页剔除，并在页头保留排除提示。

### 2. 板块热度（只做排序，不能替代三关）

```text
热度 = 32% 涨停家数 + 22% 连续性 + 24% 梯队 + 14% 资金 + 8% 高度
```

- 涨停家数：相对当日最大板块归一化。
- 连续性：昨日涨停家数占比 + 今日/昨日达到 3 家、2 家的加成。
- 梯队：高位 / 二板 / 首板各占三分之一，缺一层就少一块。
- 资金：今日、昨日净流入与板块涨幅；两日均为负时强行压低。
- 高度：板块最高板与龙头封板时间、炸板情况。

### 3. 情绪周期

五维加权：昨日涨停溢价 25%、涨停家数 20%、连板高度 20%、封板质量 20%、晋级率 15%。按分数与炸板率划分：

- 冰点退潮：分数 < 30
- 分歧退潮：炸板率 ≥ 45%，或高度 ≤ 2 且昨日溢价为负
- 主升发酵：分数 ≥ 72 且炸板率 < 24%
- 修复发酵：分数 ≥ 55
- 混沌分歧：其余情况

情绪只决定"该不该出手"的松紧，不替代主线三关。

### 4. 三种角色与评分

- **情绪连板龙**：板块情绪核心，看高度、封板质量、首封时间、换手。
- **趋势中军**：大市值、有承接、主力资金参与，看涨幅、换手与市值匹配。
- **补涨龙**：龙头打出高度后的低位补涨，看早封、封单与良性换手。
- **首板先锋**：首板强度，等二板确认，默认更保守。

综合分大致为：54% 角色分 + 30% 板块热度 + 16% 数据闸门完成度，再加少量角色修正。数据闸门未过时，龙头/补涨/首板封顶 68，中军封顶 64；新起题材封顶 60/58。分数用于横向比较，不是收益预测。

### 5. 复盘口径

- 昨日涨停溢价：昨日涨停股今日涨跌幅的平均值，并分首板 / 二板 / 高位三档。
- 晋级率：昨日首板今日成为二板及以上的比例；昨日连板今日继续涨停的比例。
- 连板天梯：按 3 板及以上、2 板、首板分层展示，避免"只看最高标"。
- 板块分布：按今日涨停家数排序，叠加三关状态与资金列。

### 6. 盘前竞价抓强（9:15–9:30）

竞价阶段按北京时间自动切换：

| 阶段 | 时间 | 程序行为 |
| --- | --- | --- |
| 试撮 | 9:15–9:20 | 计算强度，但所有 `confirm` 一律降级为 `watch`；提示可撤单 |
| 锁单 | 9:20–9:25 | 不可撤单，参考价值最高；确认条件全部生效 |
| 定稿 | 9:25–9:30 | 价格锁定；可做最后确认，等待 9:30 承接；不再新增标的 |
| 承接 | 9:30 后 | 竞价评分关闭；只按开盘承接执行或退出 |

非竞价时段 `/api/auction` 只返回下一场准备池（含老龙头画像匹配），不会用盘中涨幅伪造竞价分。

覆盖池由"最新涨停池 + 主线候选领涨股"组成，剔除 ST 与非法代码，再用腾讯批量行情补实时价。竞价分：

```text
90% ×（30% 涨幅分 + 28% 竞价额分 + 24% 板块分 + 18% 昨日封板分）× 情绪系数
+ 10% 老龙头画像分
```

其中板块分包含"同板块实时强势家数"加成；非涨停池成员封顶 82 分，避免只凭一条领涨股数据给出高分。

**确认（可执行候选）必须同时满足**：

1. 竞价分 ≥ 72；
2. 竞价涨幅在 +2% ~ +8%（翻绿或高开 > 8% 都不确认）；
3. 竞价额 ≥ 2000 万，且 ≥ 昨日成交额 2%；
4. 同板块至少 2 只个股竞价额 ≥ 1000 万且高开 ≥ 2%；
5. 所在板块三关通过；
6. 个股来自昨日涨停池（有封板质量数据）；
7. 本机已人工核验为政策 / 产业 / 事件级催化（否则前端只显示"待催化"）。

标为"纯传闻"的方向会直接从竞价清单剔除。高开、放量、共振、画像匹配等只用于解释，不替代上述硬门槛。

**边界**：公开数据源没有长期、完整、免费的集合竞价历史快照，因此本项目**无法**做严谨的竞价因子回测，也不承诺"竞价准确率"。9:20 前挂单可撤，任何结论都必须等 9:20 后复核；9:30 承接失败按失效处理。

### 7. 盘后隔夜计划（15:00 后定稿）

隔夜计划先过状态闸门，再谈个股：

| 状态 | 触发条件 | 页面结论 |
| --- | --- | --- |
| `empty` | 没有板块通过三关 | 不挂隔夜单 |
| `defend` | 有板块达标，但情绪冰点 / 退潮 | 降频观察 |
| `wait` | 有板块达标，但情绪混沌 | 等情绪确认 |
| `locked` | 竞价已开始 | 盘前不追加，只验证 |
| `preview` | 盘中打开 | 盘中预演，15:00 后重算才可作计划 |
| `ready` | 三关 + 情绪修复 / 主升 + 盘后定稿 | 可制定隔夜计划 |

候选来自通过三关的板块：优先昨日 2–5 板、非中军角色、按个股分排序；没有合适个股时用板块龙头兜底。隔夜分：

```text
56% 个股基础分 + 30% 老龙头画像分 + 14% 板块热度
```

进入推荐需：画像分 ≥ 55、隔夜分 ≥ 65、昨日 2–5 板、无炸板记录；否则只进"降级观察"。

每条计划给出固定的条件区间，而不是预测价：

- 竞价高开 **+1% ~ +4%** 执行；高开 **> +6%** 放弃；低开 **< -2%** 放弃；
- 9:20 后价格不回落，同板块至少 1 只核心共振，竞价额 ≥ 昨日成交额 3%；
- 开盘 10 分钟跌破分时均线且无承接，按失效处理；
- 止损参考：跌破昨收 -3% 或分时均线持续走弱；
- 单票 ≤ 10%，隔夜总仓 ≤ 30%，没有催化核验则不下单。

页面上的"可挂条件单"要求同时满足：状态 `ready`、模式 `final`、个股 `acceptable`、本机催化已核验。任何一项缺失，只显示"待催化核验 / 预演草稿 / 观察"。隔夜存在跳空、滑点、停牌与无法成交风险，条件单不是保本工具。

### 8. 老龙头画像（历史样本，不是准确率）

样本口径：

1. 对最近 N 个交易日（默认 30，接口限制 10–60）读取涨停池；
2. 找出当日 ≥ 2 家涨停的板块；
3. 取板块内连板高度最高且 ≥ 3 板的个股作为"老龙头样本"；
4. 用腾讯历史日线读取次一交易日：是否继续涨停、次日开盘跳空；
5. 按"代码 + 日期"去重，统计延续率、高开比例、平均 / 中位跳空。

六维分桶：连板高度、首封时间、封单 / 流通、换手率、流通市值、板块涨停家数。每个桶记录样本数、延续数、延续率与平均跳空；**少于 3 条样本的桶只展示，不参与加权**。

画像分：

```text
经验分 = 50 +（该股命中的各桶延续率均值 − 全样本延续率）× 1.8
画像分 = 62% 静态规则分 + 38% 经验分
```

静态规则分来自口诀中的龙头特征：高度、封板时间、封单、换手、市值、板块家数与情绪修正；经验分只做温和加权，避免小样本把分数推到极端。

样本累积：上游涨停池通常只保留约 15 个交易日，因此服务端每天把新样本与 `.cache/dragon-profile.json` 里的旧样本合并，上限 120 个交易日 / 600 条。`recentSamples` 返回最近 12 条；完整 `rawSamples` 只落盘，不通过 API 返回。首次构建约 10–40 秒，期间接口返回 `building:true`，页面每 3 秒轮询。

**必须说明的偏差**：画像只统计"已经走出来的高标"，存在幸存者偏差；样本量小、风格切换、监管特停都会让历史规律失效；统计未扣交易成本、滑点与无法成交。因此它是"排除明显不符合龙头特征"的过滤器，不是收益预测，更不是准确率。

## 刷新节奏

- 个股价格：交易时段 1 秒，非交易时段 15 秒；首页上证指数走同一条报价轮询。
- 上证指数分时：交易时段 3 秒，非交易时段 30 秒；后端分时缓存 2 秒，保留完整分钟点，折线以昨日收盘价作虚线基准，下方红绿柱为逐分钟成交量（收 ≥ 开红、否则绿），与折线共用同一时间轴。
- 量能对比：用沪深两市合计成交额（上证指数 + 深证成指，腾讯指数行情）对比上一有效交易日同一时点，同时显示今日总额、差额金额、差额百分比与昨日同期成交额；差额 ≥ +5% 记为放量、≤ -5% 记为缩量，其余为量平。腾讯多日分时缓存 10 分钟，避免每次刷新都拉多日数据；东财备用节点给深证指数返回的成交额明显偏小，因此不直接相加东财指数金额。
- 涨跌家数：使用东财涨跌分布（`getTopicZDFenBu`）汇总沪深两市全部正在交易的 A 股，卡片上标「两市」；这是全市场口径，不是上证指数单市场的涨跌家数。涨跌分布缓存 3 秒并随分时 3 秒轮询更新；接口异常时退回上证指数自带的涨跌家数并标注「沪市」，不会把单市场数字冒充全市场。
- 涨停封单金额：选票页每 1 秒随行情刷新，取腾讯五档买一价 × 买一量 × 100；只有最新价与买一价都贴在涨停价时才计算，炸板 / 开板后立即改为「已开板」，不保留旧封单。行情尚未回传或未请求封单时退回涨停池快照并标注「池快照」。东财备用节点给深市个股返回的现价可能滞后，封单请求统一以腾讯实时价为准。
- 榜单与情绪：交易时段 10 秒，非交易时段 60 秒。
- 竞价抓强：竞价时段每 1.5 秒；盘前每 10 秒；非竞价时段停止轮询，只保留准备池。
- 隔夜计划：交易时段每 30 秒预演；收盘后停止自动轮询，手动重算。
- 老龙头画像：磁盘缓存 6 小时；首次构建期间前端每 3 秒重试，最多 15 次。
- 页面切到后台自动暂停，回到前台立即补一次。
- 交易状态按北京时间判断：盘前、集合竞价、盘中、午间休市、已收盘、周末休市。

报价接口有 850ms 缓存，榜单接口有 8 秒缓存，当日板块 / 个股资金有 20 秒缓存；手动刷新会跳过后端榜单缓存强制重建。竞价阶段复用报价缓存，1.5 秒轮询足够拿到新的撮合快照。

## 准确率与验证

本项目不提供"准确率"数字，原因不是谦虚，而是目前没有可靠的验证基础：

- 竞价：公开数据源不提供长期完整的集合竞价历史快照，无法回测"9:20 竞价强度 → 次日收益"。
- 画像：延续率是历史样本统计，未扣交易成本、滑点、无法成交与停牌，不等于策略胜率。
- 选股：分数用于横向比较与排除，不是收益预测；数据降级时会保守降级，而不是补齐假数据。

建议按以下方式自行做前向验证：

1. 每个交易日记录候选：日期、代码、板块、角色、画像分、竞价硬条件、是否执行；
2. 次日记录：开盘跳空、是否延续、收盘结果、止损是否触发；
3. 至少连续 20–60 个交易日，统计候选数、执行数、延续率、平均跳空、假信号比例、最大单笔亏损；
4. 与"同板块随机 3 板股"的基线对比；跑不赢基线，说明当前画像没有增量信息；
5. 情绪退潮、数据源连续降级、画像样本不足 20 个交易日时，暂停使用并复盘。

只有可重复的样本外验证，才配叫"准确率"。

## 已知限制

- 龙头判定基于"涨停池 + 板块梯队 + 资金"的公开数据，无法判断新闻真伪；题材催化必须人工核验并自行承担判断责任。
- 集合竞价没有权威、免费、长期的历史快照，因此竞价规则无法做严格回测；本项目的竞价评分只用于实时排除虚强、追高与孤军，不承诺胜率。
- 老龙头画像存在幸存者偏差：只统计已经走出来的高标；上游涨停池约保留 15 个交易日，本机累积上限 120 日 / 600 条，样本量仍需时间。
- 分桶延续率在样本少于 3 条时不参与加权；即使样本足够，风格切换也可能让规律失效。
- 东方财富 `push2 / push2his` 的部分 CDN 节点在个别网络下会被重置；程序会自动切到同源 `push2test`，若仍失败则资金关显示未通过，不会用假数据补齐。
- 板块目录优先使用实时目录（约 496 个行业板块），实时目录失败时退回本地 `boards.json`。极少数行业名仍可能无精确对应，页面会显示"板块资金映射缺失"。
- 资金近似口径（今日 + 5 日为正）只作参考，**不会**让板块通过"资金连续流入"这一关；必须今日与昨日均为真实净流入。
- 涨停池在盘中会变化，首次封板时间、炸板次数等字段以接口返回为准；收盘后复盘更稳定。
- 不同数据源之间可能有几秒延迟，价格与榜单不完全同步是正常现象。
- 隔夜条件单不是自动交易：不会连接券商、不会代下单，跳空、滑点、停牌都可能让计划失效。
- 本项目没有任何"历史回测胜率"背书，也不构成投资建议。
