# 龙脉 · A股主线龙头雷达

一个移动端优先的 Vue 3 H5，用来把"先定主线，再选个股"拆成可检查的数据闸门：主线是否连续、梯队是否完整、资金承接是否有四项证据（主力两日净流入、量能、封单、溢价/晋级）。并在盘后把情绪周期、节点票（空间 / 卡位 / 转势 / 补涨）、连板高度、流通市值、弱转强、龙头基因与历史画像合成隔夜条件单，在盘前 9:15–9:30 用集合竞价数据做最后复核。竞价 9:20–9:30 与盘中 9:30–15:00 可开启实时预警：只对仍未封板、还能挂单的强势候选弹出提醒，并写入本机预警中心与推荐榜；已封板 / 贴涨停的票不提醒。每条推荐标注首次推荐时间和最近更新时间，当天记录存在浏览器本地，刷新页面不会清空。行情来自公开网页接口，不接券商、不自动下单，只做观察与复盘。

> 先说清楚：GitHub 上不存在经过长期实盘验证、可以稳定"高准确率抓龙头"的开源项目，也没有可公开复现的"竞价高胜率模型"。本项目参考的是数据工程与量化研究的通用做法（见文末），选股口径来自你给出的口诀，并尽量把"数据不足"如实暴露出来，而不是编造胜率。

## 快速开始

要求 Node.js 16 及以上（本项目在 16.20.2 上构建通过）。

```bash
npm install
npm run dev:all      # API :8787 + Vite :5173，开发时打开 http://127.0.0.1:5173
```

生产模式（单端口，由 Node 直接托管构建产物）：

```bash
npm run build
npm start            # http://127.0.0.1:8787
```

如果 npm 走了本机代理并报 `ECONNREFUSED 127.0.0.1:7897`：

```bash
npm --proxy=null --https-proxy=null install --registry=https://registry.npmmirror.com
```

API 端口可通过环境变量修改：`PORT=9000 npm start`。

如果本机已有旧版本进程占着 8787，而新页面打开竞价 / 隔夜出现 404，说明前端已是新版、后端还是旧进程。请另起端口验证：

```bash
PORT=8793 npm start   # 打开 http://127.0.0.1:8793
```

本次验收使用 `8795`；如果它也被占用，可用 `PORT=8800 npm start`。旧的 `8787 / 8788` 进程没有竞价 / 隔夜 / 画像接口，`8793` 有接口但没有最新的资金兜底和上证指数，都不要用它们判断新版功能。新版前端一旦发现后端缺少新字段，会在页面顶部显示"当前连接的是旧后端"，并给出 `8795` 入口；竞价等接口 404 时也会直接提示正确地址。

## 页面

- **主线**：上证指数实时条（含当日分时折线、昨收基准、红绿分时量、较昨日同期量能对比与沪深两市涨跌家数）、今日决策闸门、情绪五维评分、连续两日主线候选、新起题材（仅观察）、退潮掉队方向、三关口径说明。
- **选票**：按角色筛选的观察池，剔除科创板 688/689、创业板 300/301 的 20cm；实时价格 1 秒刷新，涨停标的显示实时封单金额与占流通比例，开板立即提示；点开单票可看分时结构、关键数据、角色定位、数据证据与风险纪律。
- **竞价**：三个子页签。
  - **竞价抓强 / 盘中实时抓板**：竞价 9:15–9:30 每 1.5 秒刷新，按 9:15 试撮 / 9:20 锁单 / 9:25 定稿 / 9:30 承接分阶段；盘前推荐只保留最多 3 只「高置信」，其余强势票只进观察池，不冒充推荐。9:30–15:00 切到盘中实时抓板，按封板确认、近板强度、量比、板块共振与弱转强排序。非交易时段只展示下一场准备池，不伪造竞价分。
  - **隔夜计划**：收盘后生成条件单草稿，只留最强 3 只、按隔夜分排序；今日一字 / 秒板不进三强。列出触发、失效、止损、仓位和跳空区间；只在三关通过且情绪修复 / 主升时给出"可制定"，催化必须人工核验后才显示"可挂条件单"。
  - **老龙画像**：回溯板块内 3 板以上领涨股的次日延续率与隔夜跳空，按六个维度分桶统计，并随本机使用逐日累积样本。
- **复盘**：昨日涨停今日溢价、首板/连板晋级率、连板天梯（含昨日各高度层的实时晋级 / 淘汰流转与连板淘汰名单）、涨停板块分布、炸板与跌停池、自动复盘结论。
- **战法**：完整口诀、标准化盘后 / 盘前 / 开盘流程、四道闸门、竞价五条硬规则、隔夜六条硬规则、三种龙头角色、老龙画像口径、打板客审美（北京炒家 / 92科比 / 全能的野人公开思路与已编码条件）、"准确率"验证方法、公开评分公式、数据来源与本工具"不做什么"。
- **实时预警与推荐榜（全局）**：竞价 9:20–9:30 与盘中 9:30–15:00 每 3–5 秒检查，只弹未封板、涨幅 +2% ~ +8%、距涨停 >0.3 个点、预警分 ≥70 的强势票；已封板、贴涨停、9:15–9:20 试撮、午间冻结、20cm 以及「三板组 / 核按钮」高风险都不弹。每轮最多只提醒预警分最高的 1 只；竞价页与预警中心另有最多 3 只的推荐榜，高置信优先、同层按预警分排序，名次即排序。盘前「高置信」还要求板块三关通过、基因 ≥70、涨幅 ≤7%、竞价额 ≥ 昨日成交 3%、预警分 ≥78 且无核按钮风险；这是更严的规则层，不是回测胜率。每条推荐标注「推荐 HH:MM:SS」与「最近 HH:MM:SS」；当天推荐、出榜记录与时间存在浏览器 `localStorage`，刷新页面不会清空，封板 / 走弱 / 不再达标的票移到可见历史而不是消失。同一代码每天只弹一次，首次连接只做一次汇总。顶部铃铛进入预警中心，可开关未核验催化提醒、提示音与桌面通知，并查看触发记录、推荐榜与去核验入口。预警只是条件触发，不是买入指令。

## 接口

所有接口均为本机 Node 服务提供，默认端口 `8787`：

| 接口 | 说明 |
| --- | --- |
| `GET /api/dashboard?refresh=1` | 聚合看板：上证指数、情绪、板块三关、梯队、选票、复盘、数据降级项 |
| `GET /api/quotes?secids=0.002156,1.600410` | 批量实时报价（最多 80 只，支持 `1.000001` 上证指数）；`seal=1` 时附带腾讯五档买一、`sealed` 与 `sealFund`（涨停封单金额） |
| `GET /api/trend?secid=0.002156` | 单票 / 板块分时；`compare=1` 时附带较上一有效交易日同期量能对比；上证指数（`1.000001`）额外返回 `breadth`（沪深两市涨跌家数）与 `marketCompare`（沪深两市合计成交额对比） |
| `GET /api/auction` | 竞价 / 盘中抓强：阶段、候选、试撮 / 锁单 / 定稿、观察池；盘前 `alertBoard` 最多 3 只、高置信优先并按预警分降序、带首次推荐时间与 `confidence`；盘中同样返回 3 只推荐榜。观察池不是推荐 |
| `GET /api/alerts` | 实时预警：竞价 9:20–9:30 与盘中 9:30–15:00 返回未封板、距涨停 >0.3、涨幅 +2% ~ +8%、预警分 ≥70 的候选，每轮最多弹 1 只；`board` 返回最多 3 只推荐榜，盘前高置信优先，均不含 20cm；附带窗口、阈值、可买过滤、首次推荐时间与去重说明；与 `/api/auction` 共用 1.5 秒短缓存 |
| `GET /api/rec-audit?days=10&refresh=1` | 推荐结果核对：只统计复盘明确给出的晋级榜 / 明日待选（剔除一字 / 秒板），按次日日线核对竞价缺口、触发买点、开盘→收盘、晋级与触板；附台账定稿状态与口径说明 |
| `GET /api/overnight` | 盘后隔夜计划：状态闸门、条件单、观察、未过三关板块；`recommendations` 最多 3 只、按隔夜分降序，今日一字 / 秒板不进三强，并返回统一 `plan` 供复盘页复用 |
| `GET /api/dragon-profile?days=30&refresh=1` | 老龙头画像：样本统计、六维分桶、最近样本；首次可能返回 `building:true`，前端每 4 秒重试 |
| `GET /api/health` | 服务状态、看板年龄、画像摘要 |

## 数据来源

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 涨停池 / 炸板池 / 跌停池 | 东方财富 `push2ex` | 涨停家数、连板数、首封时间、封单、炸板次数、行业板块 |
| 个股实时报价 | 腾讯 `qt.gtimg.cn` 批量行情 | 1 秒级价格、涨跌幅、换手、流通市值、五档买一价 / 买一量、涨停封单金额；选票页带 `seal=1` 时以腾讯价校准现价，避免东财备用节点的深市滞后价 |
| 上证指数 | 东方财富 `push2` 批量行情（`1.000001`），失败切 `push2test`；分时走 `trends2`；沪深两市成交额与昨日同期用腾讯指数行情 / 多日分时 | 首页点位、涨跌幅、沪市成交额、今开 / 最高 / 最低、涨跌家数、当日分时折线与逐分钟红绿成交量、沪深两市成交额及较昨日同一时点的放量 / 缩量结论（含今日总额、差额金额与百分比） |
| 板块当日主力资金 | 东方财富 `push2`，失败自动切 `push2test` 同源节点 | 今日板块主力净流入 |
| 板块历史资金 | 东方财富 `push2his`，失败自动切 `push2test` 同源节点 | 连续 2 日 / 5 日资金判断 |
| 历史日线 | 腾讯 `web.ifzq.gtimg.cn` 前复权日线 | 老龙头样本的次日延续率、隔夜跳空 |
| 集合竞价报价 | 腾讯批量行情 + 东方财富涨停池 | 9:15–9:30 竞价涨幅、竞价额、板块共振 |
| 板块目录 | 东方财富 `push2/push2test` 实时目录，失败退回本地 `server/data/boards.json` | 行业板块与资金接口映射 |
| 题材催化 | 人工核验，仅存本机 localStorage | 政策 / 产业 / 事件 / 传闻 / 暂无 |
| 老龙头样本累积 | 本机 `.cache/dragon-profile.json` | 跨交易日累积，上限 120 日 / 600 条 |

这些都不是官方开放 API，可能限流、改字段或临时不可用。程序的处理原则是：

1. 单次失败不阻塞整页，成功的数据继续展示；当日资金与历史资金分开计失败次数，单只板块异常不会连坐整轮；
2. 只有关键字段确实没有替代数据时，页面顶部才出现"数据源部分降级"提示，并列出失败项；
3. 资金缺失时闸门显示未通过，选票统一降级为"仅观察"，不会用 0 或假数据补齐；
4. 当日 / 历史资金各自连续失败 3 次才进入 60 秒冷却；历史缓存 10 分钟、当日资金缓存 20 秒；
5. `push2 / push2his` 连接被重置时自动切换同源 `push2test` 节点，并记住主节点故障 2 分钟，期间直接走备用节点，避免反复白等；
6. 当日明细失败时优先回退到板块列表里的真实 `f62`，昨日资金优先回退到本机快照；两者都有时不再误报降级；
7. 本机 `.cache/flow-daily.json` 会记录每次成功读到的板块当日资金，作为第二天"连续流入"的本地快照。

## 核心算法

### 1. 三关定主线

一个板块必须同时通过以下三项，才算"三关通过"：

1. **连续两日靠前**：今日与昨日涨停家数都 ≥ 2，且今日排名 ≤ 8、昨日排名 ≤ 10。
2. **梯队完整**：板块内同时存在高位连板（≥ 3 板）、中位二板、低位首板。
3. **资金连续流入**：今日与昨日板块主力均为净流入。只有今日流入、昨日数据缺失时，如果 5 日累计为正，会显示金色"≈ 近似"标记供参考，但**不会**让板块通过资金关，也不会解除"仅观察"状态。

任何一关不过，都不会给出可执行结论。没有板块通过三关时，顶部直接显示"空仓等待"，个股分数被限制在观察区间。

首页主线候选按「三关通过数 → 热度 → 连板高度」排序，强度第一的方向单独置顶，其余方向默认收起，避免卡片堆叠。情绪分只描述环境温度，不解除三关限制：情绪高但没有板块过三关，仍然只观察核心、不追高。

催化是单独的人工核验项：板块标记政策 / 产业 / 事件且三关通过后，个股才按"综合分"展示；未标记或标为"暂无催化"的，一律显示「待催化」并压成观察分；标为"纯传闻"的方向会直接从选票页剔除，并在页头保留排除提示。

### 2. 板块热度（只做排序，不能替代三关）

```text
热度 = 32% 涨停家数 + 22% 连续性 + 24% 梯队 + 14% 资金 + 8% 高度
```

- 涨停家数：相对当日最大板块归一化。
- 连续性：昨日涨停家数占比 + 今日/昨日达到 3 家、2 家的加成。
- 梯队：高位 / 二板 / 首板各占三分之一，缺一层就少一块。
- 资金：今日、昨日净流入与板块涨幅；两日均为负时强行压低。
- 高度：板块最高板与龙头封板时间、炸板情况。

### 3. 情绪周期

五维加权：昨日涨停溢价 25%、涨停家数 20%、连板高度 20%、封板质量 20%、晋级率 15%。按分数与炸板率划分：

- 冰点退潮：分数 < 30
- 分歧退潮：炸板率 ≥ 45%，或高度 ≤ 2 且昨日溢价为负
- 主升发酵：分数 ≥ 72 且炸板率 < 24%
- 修复发酵：分数 ≥ 55
- 混沌分歧：其余情况

情绪只决定"该不该出手"的松紧，不替代主线三关。

### 4. 三种角色与评分

- **情绪连板龙**：板块情绪核心，看高度、封板质量、首封时间、换手。
- **趋势中军**：大市值、有承接、主力资金参与，看涨幅、换手与市值匹配。
- **补涨龙**：龙头打出高度后的低位补涨，看早封、封单与良性换手。
- **首板先锋**：首板强度，等二板确认，默认更保守。

综合分大致为：54% 角色分 + 30% 板块热度 + 16% 数据闸门完成度，再加少量角色修正。数据闸门未过时，龙头/补涨/首板封顶 68，中军封顶 64；新起题材封顶 60/58。分数用于横向比较，不是收益预测。

### 5. 复盘口径

- 昨日涨停溢价：昨日涨停股今日涨跌幅的平均值，并分首板 / 二板 / 高位三档。
- 晋级率：昨日首板今日成为二板及以上的比例；昨日连板今日继续涨停的比例。
- 连板天梯：按 3 板及以上、2 板、首板分层展示，避免"只看最高标"；7 层以上合并标 `+`。
- 天梯流转：按昨日高度层统计今日晋级、淘汰与炸板，随涨停池约 10 秒刷新；淘汰含首板，名单只列昨日 ≥2 连板，盘中回封会自动移回天梯。
- 板块分布：按今日涨停家数排序，叠加三关状态与资金列。
- 炸板压力：按连板高度与炸板次数排序列出样本，并补换手与主力净流入；放量炸板 + 主力净流出标记为出货风险样本，不进入明日待选。

**短线作战室（复盘页顶部）**：先把今日走势拆成情绪 / 高度 / 中位 / 前排四段，再只对合格前排做明日晋级估算。

- 前排过滤：只保留 2–5 板；节点分 ≥50、非风险节点；炸板 ≤2 次、换手 ≤30%、封单 ≥0.7%、非尾盘板；剔除三板组核按钮（小盘冷门票一字 / T 字缩量加速到 3–4 板、封单异常大、无板块主线）、同高度 ≥2 且非最高板的拥挤、距顶 ≥2 板的中位断层、梯队跟随与后排跟风；板块要求三关就绪，或至少 1 关 + 热度 ≥40。剔除项会写明原因（三板组核按钮 / 同高度拥挤 / 中位断层 / 脏板 / 尾盘板 / 后排跟随）。
- 三板组 / 核按钮：不是"同高度三板"。指小盘冷门票用一字 / T 字缩量加速到 3–4 板，封单异常大、换手极小、板块没有梯队，随后在竞价或早盘撤单往下砸（核按钮），常演变成天地板 / A 杀。风险分由连板高度、流通盘、换手、首封、封单与板块共振合成；高风险不进晋级榜 / 明日待选 / 预警，只在「三板组核按钮」面板列为观察；中风险降权并标「防核按钮」。
- 同高度拥挤 / 中位断层：同高度 ≥2 且非最高板只是卡位拥挤；距顶 ≥2 板是中位断层。二者是身位风险，不是三板组，复盘里分别标注。
- 晋级估算：规则估算（`平滑基准 × 高度系数 × 前排质量 × 瑕疵折扣`）与历史校准模型按保守权重合成，输出 ±9pp 区间。规则基准取今日实测的首板→二板、连板→连板晋级率，并按先验（首板 26% / 连板 40%，权重 k=14）平滑；小样本时规则部分仍主要受先验约束。
- 历史校准：用东方财富涨停池构造"T 日收盘特征 → T+1 是否晋级"样本，特征为首封时间、封流比（封单/流通）、封成比（封单/成交额）、炸板次数、板位、流通盘、板块涨停家数、板块龙一与市场晋级率；按日 walk-forward（前一日及以前训练、后一日检验），从不使用未来数据。只有同时满足 Brier 改善、AUC ≥0.55、Top10% 晋级率高于基准、且 2 板+ 子集同样有效时，才给模型最多 45% 权重；不达标就权重为 0，完全回到规则口径。样本只有约 15 个交易日并在本地按 `date|code` 累积，校准是排序与风险过滤，不是胜率承诺。
- 龙头评分：42% 节点 + 16% 高度适配 + 10% 市值适配 + 14% 封板质量 + 12% 板块质量 + 6% 弱转强 − 尾盘扣分；从合格前排里选，不是简单拿最高板。
- 高度风向标：最高板若炸板多、尾盘板、薄封或板块 0 关，只给参考晋级，不进入晋级榜，只看不接。
- 出手判定：三关空仓 / 防守期观察 / 无合格前排观察 / 有断层或高位风险时只做分歧核心（≤2 成、单票 ≤1 成）/ 进攻窗口小仓（≤3 成）。弱势切核心抱团、分歧切核心都只做最强核心，核心不回封当天不交易。

**打板客审美（复盘页作战室下方）**：把北京炒家、92科比、全能的野人的公开打法拆成可检查条件，输出"今日审美命中 / 明日打板待选 / 只观察"三组。

- 审美分（只排序，不是胜率）：30% 封板质量 + 18% 板块质量 + 14% 节点 + 12% 身位 + 8% 市值 + 8% 换手 + 5% 弱转强 + 5% 板块地位。
- 今日命中：1–3 板；板块热度 ≥45 且同板 ≥3 家，或至少过 1 关；炸板 <3、换手 ≤40%、封单 ≥0.7%、非尾盘板；审美 ≥62；同板块最多 2 只、总共最多 5 只。3 板只在非跟随节点保留；20cm 不进入命中。
- 明日待选：1–2 板；板块三关全过且是板块龙一、节点非风险；封单 ≥0.7%、非尾盘、换手 ≤30%、流通 20–300 亿；首板炸板 ≤1 且首封 ≤10:30，二板炸板 ≤2 且不能是梯队跟随；审美 ≥65；最多 5 只、同板块最多 2 只。龙一是 3 板或只过 1–2 关的票降为观察，不降标准补位；今日一字 / 秒板买不到，同样不进待选，只观察竞价换手；催化未核验前只算待选，不解除观察；20cm 不进入待选。
- 只观察：方向对但板块三关未全过 / 板块龙一不在 1–2 板 / 封单薄 / 首封晚 / 炸板多 / 换手过热 / 流通不合 / 同板块名额已满，只写原因，不给买点。待选为 0 时直接提示空仓（龙空龙），不降标准补位。
- 执行规则：首板只做一进二验证，仓位 0.5–1 成；二板单票 ≤1 成，与晋级榜重叠只算一笔；1 板竞价 +1%–4%、2 板 +1%–3%，竞价额 ≥ 今日成交 3%，只做分歧回封 / 分时均线转强，高开 >5%–6% 或秒板放弃。
- 口径与边界：北京炒家偏首板套利、板块效应、缩量二板；92科比只做高位龙头或低位首板 / 一进二，避开中位；全能的野人强调龙空龙、只做龙一。以上来自公开访谈与复盘，公开胜率是自我描述、未经本机验证；板块使用行业口径，不等同概念题材，催化与主线仍需人工核验。

### 6. 盘前竞价抓强（9:15–9:30）

竞价阶段按北京时间自动切换：

| 阶段 | 时间 | 程序行为 |
| --- | --- | --- |
| 试撮 | 9:15–9:20 | 计算强度，但所有 `confirm` 一律降级为 `watch`；提示可撤单 |
| 锁单 | 9:20–9:25 | 不可撤单，参考价值最高；确认条件全部生效 |
| 定稿 | 9:25–9:30 | 价格锁定；可做最后确认，等待 9:30 承接；不再新增标的 |
| 承接 | 9:30 后 | 竞价评分关闭；只按开盘承接执行或退出 |

非竞价时段 `/api/auction` 只返回下一场准备池（含老龙头画像匹配），不会用盘中涨幅伪造竞价分。

覆盖池由"最新涨停池 + 主线候选领涨股"组成，剔除 ST 与非法代码，再用腾讯批量行情补实时价。竞价分：

```text
90% ×（30% 涨幅分 + 28% 竞价额分 + 24% 板块分 + 18% 昨日封板分）× 情绪系数
+ 10% 老龙头画像分
```

其中板块分包含"同板块实时强势家数"加成；非涨停池成员封顶 82 分，避免只凭一条领涨股数据给出高分。

**确认（可执行候选）必须同时满足**：

1. 竞价分 ≥ 72；
2. 竞价涨幅在 +2% ~ +8%（翻绿或高开 > 8% 都不确认）；
3. 竞价额 ≥ 2000 万，且 ≥ 昨日成交额 2%；
4. 同板块至少 2 只个股竞价额 ≥ 1000 万且高开 ≥ 2%；
5. 所在板块三关通过；
6. 个股来自昨日涨停池（有封板质量数据）；
7. 本机已人工核验为政策 / 产业 / 事件级催化（否则前端只显示"待催化"）。

标为"纯传闻"的方向会直接从竞价清单剔除。高开、放量、共振、画像匹配等只用于解释，不替代上述硬门槛。竞价榜里已经封板的票只标「已封板 · 买不进 / 排队观察」，不再显示为可执行候选；竞价预警也只提醒未涨停票。盘中时段改用实时封板 / 近板强度 / 量比 / 板块共振排序，预警只提醒未封板、还能挂单的票，已封板只排队观察。推荐榜最多 3 只，盘前高置信优先、同层按预警分从强到弱，名次就是排序；每条带首次推荐时间，刷新页面不清空。科创板 688/689、创业板 300/301 的 20cm 不进入竞价榜、盘中榜、准备池与预警，避免把 10cm 与 20cm 的打板纪律混在一起。

**盘前高置信（比推荐榜更严的一层）**：只认 9:20 后确认、板块三关通过、基因 ≥70、涨幅 +2% ~ +7%、竞价额 ≥ 昨日成交 3%、预警分 ≥78，且没有防核按钮 / 核按钮风险的票；盘前最多 3 只。高置信为空时，页面不会用观察票补位。它是为了减少"追高、孤军、买不进"样本的规则层，不是历史准确率；竞价仍无法严谨回测。

**观察池**：竞价页下半部分的 5 只强势候选只解释"为什么关注"，不是推荐。它们可能仍在等催化、等板块共振或等 9:25 定稿；把观察池当买入清单，是本工具明确反对的用法。

**边界**：公开数据源没有长期、完整、免费的集合竞价历史快照，因此本项目**无法**做严谨的竞价因子回测，也不承诺"竞价准确率"。9:20 前挂单可撤，任何结论都必须等 9:20 后复核；9:30 承接失败按失效处理。

### 7. 盘后隔夜计划（15:00 后定稿）

隔夜计划先过状态闸门，再谈个股：

| 状态 | 触发条件 | 页面结论 |
| --- | --- | --- |
| `empty` | 没有板块通过三关 | 不挂隔夜单 |
| `defend` | 有板块达标，但情绪冰点 / 退潮 | 降频观察 |
| `wait` | 有板块达标，但情绪混沌 | 等情绪确认 |
| `locked` | 竞价已开始 | 盘前不追加，只验证 |
| `preview` | 盘中打开 | 盘中预演，15:00 后重算才可作计划 |
| `ready` | 三关 + 情绪修复 / 主升 + 盘后定稿 | 可制定隔夜计划 |

候选来自通过三关的板块，另补入"不是板块最高板、但封板质量更干净"的强封核心（2 板以上、0 炸、封单厚、换手低），避免只看龙头而漏掉真正的连板核心。隔夜分：

```text
50% 个股基础分 + 30% 龙头基因分 + 20% 板块热度
```

进入严格推荐需：板块三关通过、画像分 ≥ 55、隔夜分 ≥ 65、昨日 2–5 板、无炸板记录、节点分 ≥ 50 且不是高风险节点；否则只进"降级观察"。

严格候选还要再收口：**盘后只留最强 3 只，按隔夜分降序，名次就是排序；今日一字 / 秒板不进三强**（次日大概率高开，给不了舒服区间）。不足 3 只就空着，不用弱票补位。复盘页的「隔夜三强」直接复用同一份候选与统一计划，盘后定稿后才标"可作条件单草稿"；盘中打开只标预演。

准备池只收 2 板以上，且剔除科创板 688/689、创业板 300/301 的 20cm；按多因子排序，再扣核心修正：

```text
30% 基因 + 14% 基础分 + 10% 板块热度 + 8% 弱转强
+ 10% 情绪适配 + 12% 节点 + 10% 连板高度 + 6% 流通市值
```

核心修正：

- 炸板每次 −4（上限 −24），换手 >20% 每点 −0.6（上限 −14）；
- 容量中军 −4（流通 ≥80 亿且成交 ≥10 亿，或流通 ≥200 亿）；5 板以上 −6；
- 封单 <1% −6，流通 <20 亿 −4，首封晚于 10:30 −4。

节点票模型把连板结构拆成可解释的层级：

| 节点 | 判定 | 处理 |
| --- | --- | --- |
| 破局龙 | 修复 / 主升期的市场空间板（最高板 ≥3），封板干净 | 节点优先级最高，但仍需三关与催化 |
| 空间板 | 与市场最高板同高 | 情绪高度锚；高位炸板多时降为「高位空间板」 |
| 卡位节点 | 距空间板 1 板且自身 ≥3 板 | 龙头分歧时的第一卡位 |
| 转势板 | 跌停反包 / 炸板回封 / 烂板转强 | 情绪由冰点转修复的关键节点 |
| 梯队节点 | 距空间板 2 板的中位连板 | 只在板块三关与强封条件下使用 |
| 补涨节点 | 空间板之外的低位强封核心（2 板、0 炸、封单厚、换手低） | 走补涨 / 接力，不追高 |
| 梯队跟随 | 距空间板 ≥3 板且封板质量一般 | 只解释，不占准备池前排 |

情绪适配按冰点 / 退潮 / 混沌 / 修复 / 主升打分，并用进攻信号、昨日溢价、晋级率、炸板率修正；连板高度相对**市场空间板**计算，离顶 1 板价值最高，离顶 ≥3 板只是跟随；流通市值 50–120 亿最适配短线，200 亿以上按中军降权，500 亿以上明显降权。节点分还会再扣炸板与过热换手，避免"高度最高但封板最脏"的票被误排到前排。

准备池分为 `核心先锋 / 分歧转强 / 容量中军 / 高位分歧`，只解释、不挂单；不足 5 只不硬凑。炸板多、换手过热的大市值中军即使连板更高，也会被降到观察区并明示扣分原因。

每条计划给出固定的条件区间，而不是预测价：

- 竞价高开 **+1% ~ +4%** 执行；高开 **> +6%** 放弃；低开 **< -2%** 放弃；
- 9:20 后价格不回落，同板块至少 1 只核心共振，竞价额 ≥ 昨日成交额 3%；
- 开盘 10 分钟跌破分时均线且无承接，按失效处理；
- 止损参考：跌破昨收 -3% 或分时均线持续走弱；
- 单票 ≤ 10%，隔夜总仓 ≤ 30%，没有催化核验则不下单。

页面上的"可挂条件单"要求同时满足：状态 `ready`、模式 `final`、个股 `acceptable`、本机催化已核验。任何一项缺失，只显示"待催化核验 / 预演草稿 / 观察"。隔夜存在跳空、滑点、停牌与无法成交风险，条件单不是保本工具。

### 8. 老龙头画像（历史样本，不是准确率）

样本口径：

1. 对最近 N 个交易日（默认 30，接口限制 10–60）读取涨停池；
2. 找出当日 ≥ 2 家涨停的板块；
3. 取板块内连板高度最高且 ≥ 3 板的个股作为"老龙头样本"；
4. 用腾讯历史日线读取次一交易日：是否继续涨停、次日开盘跳空；
5. 按"代码 + 日期"去重，统计延续率、高开比例、平均 / 中位跳空。

六维分桶：连板高度、首封时间、封单 / 流通、换手率、流通市值、板块涨停家数。每个桶记录样本数、延续数、延续率与平均跳空；**少于 3 条样本的桶只展示，不参与加权**。

画像分：

```text
经验分 = 50 +（该股命中的各桶延续率均值 − 全样本延续率）× 1.8
画像分 = 62% 静态规则分 + 38% 经验分
```

静态规则分来自口诀中的龙头特征：高度、封板时间、封单、换手、市值、板块家数与情绪修正；经验分只做温和加权，避免小样本把分数推到极端。

样本累积：上游涨停池通常只保留约 15 个交易日，因此服务端每天把新样本与 `.cache/dragon-profile.json` 里的旧样本合并，上限 120 个交易日 / 600 条。`recentSamples` 返回最近 12 条；完整 `rawSamples` 只落盘，不通过 API 返回。首次构建约 10–40 秒，期间接口返回 `building:true`，页面每 3 秒轮询。

**必须说明的偏差**：画像只统计"已经走出来的高标"，存在幸存者偏差；样本量小、风格切换、监管特停都会让历史规律失效；统计未扣交易成本、滑点与无法成交。因此它是"排除明显不符合龙头特征"的过滤器，不是收益预测，更不是准确率。

### 9. 实时预警与推荐榜（竞价 9:20–9:30 + 盘中 9:30–15:00，只提醒未封板）

预警与竞价榜 / 盘中榜的综合分分开算，目的只有一个：在还能挂单的时候提醒，而不是涨停封死后才复盘。

1. **时间窗口**：竞价 9:20–9:25（不可撤单）、9:25–9:30（定稿）与盘中 9:30–15:00 检查。9:15–9:20 试撮可撤单不提醒；午间 11:30–13:00 冻结不新增；休市不扫描。已封板、贴涨停的票不弹。
2. **可买过滤**：`sealed === true`、`gapToLimit <= 0.3`、涨幅不在 +2% ~ +8% 的候选全部排除；贴涨停或封死买不进的不弹。科创板 688/689、创业板 300/301 的 20cm 也直接排除，不进入预警与推荐榜。
3. **质量闸门**：基因 ≥65；板块三关通过或板块今日 / 昨日涨停 ≥5 家；预警分 ≥70。竞价阶段行情已返回成交额时，还要求竞价额 ≥2000 万且 ≥昨日成交 2%；盘中阶段有量比数据时要求量比 ≥1.0；成交额缺失时不臆造，只标注待行情更新。**三板组 / 核按钮高风险直接不提醒**：小盘冷门票用一字 / T 字缩量加速到 3–4 板、封单极大、无板块主线、从未分歧，容易在竞价撤单往下砸；缩量加速的中风险票会降权并标「防核按钮」。
4. **预警分口径**：竞价预警分 = 基因 50% + 竞价强度 30% + 板块 12% + 昨日涨停池 8%；盘中预警分 = 基因 45% + 近板强度 25% + 量比 15% + 板块 10% + 昨日涨停池 5%。两者都与榜单综合分不是同一口径。
5. **数量与排序**：推荐榜最多 3 只，盘前高置信优先、同层严格按预警分从强到弱（同分再比综合分），页面名次就是排序；每轮最多只弹预警分最高的 1 只，避免刷屏。盘前高置信额外要求板块三关通过、基因 ≥70、涨幅 ≤7%、竞价额 ≥ 昨日成交 3%、预警分 ≥78 且无防核按钮 / 核按钮风险；高置信为空时不补位。
6. **时间标注与刷新保留**：服务端按「交易日 + 代码」记录首次推荐时间，重复扫描不会改写；前端把推荐记录写入 `localStorage` 的 `longmai.alerts.recs.v1`，每条显示「推荐 HH:MM:SS」与「最近 HH:MM:SS」。刷新页面、重新打开都保留当天推荐和名次。封板 / 走弱 / 不再达标的票移到「出榜推荐」可见历史，不会凭空消失；只有手动清空记录才删除。
7. **催化与三关**：纯传闻直接不提醒；催化未核验或板块三关未过仍可弹"观察预警"，但明确标注不解除观察；只有催化已核验且板块三关通过才显示"可执行"。可在预警中心关闭"未核验催化也提醒"。
8. **去重**：去重键为「交易日 + 代码」，同一只票每天最多弹一次；首次连接 / 首轮扫描只汇总一次，之后新达标的票逐只弹出。
9. **空状态**：当前没有未封板且达标的票时，推荐榜明确显示空状态，不拿后排杂毛凑数；已封板只排队观察，空仓等待也是有效决策。
10. **提示与限制**：页面顶部非阻塞浮层（单只约 16 秒、汇总约 22 秒自动收起，记录仍保留在预警中心）、可选两短声提示音、可选浏览器桌面通知。页面必须保持打开，浏览器后台节流、网络延迟和接口限流都会导致漏报；没有服务器推送。竞价是撮合、盘中是连续竞价，挂单不保证成交，封板 / 炸板不回封 / 冲高回落都按失效处理。
11. **本轮筛选（为什么没弹）**：预警中心顶部显示本轮漏斗——扫描多少只强势候选、多少只达标、被哪一关挡下（已封板 / 买不进、涨幅低于 +2%、涨幅高于 +8%、基因不足、板块未共振、竞价额占比不足、量比不足、预警分不足），并列出最接近达标的 3 只票及其卡住原因。漏斗每轮随 `/api/alerts` 返回，空榜也是有效结果；可以据此判断是"严格条件没有合格票"还是"行情 / 接口没回来"，而不是靠猜。午间冻结、休市或页面没开时，打开预警中心会读取 `/api/alert-diagnostics` 的服务端留痕，显示"服务端留痕 HH:MM"；它只解释筛选过程，不代表当前价格。

> 预警是"条件触发"而不是"买入信号"。同一套引擎只负责排除虚强、后排与孤军；它无法判断新闻真伪，也无法预测次日溢价。已封板后再提醒没有交易价值，所以本工具直接不弹；没有合格票时就诚实空着。

**诊断留痕**（均在 `.cache/` 下，运行时生成、不入库）：

- `alert-diagnostics.json`：交易时段每 30 秒记录一次当前阶段、漏斗计数、推荐榜代码与达标状态，用于事后回答"某个时点到底卡在哪一关"。
- `alert-polls.json`：前端轮询 `/api/alerts` 的计数与首末时间，用于区分"服务端没票"与"页面没轮询"。
- `auction-snapshots/YYYYMMDD-HHMM.json`：竞价 / 等待时段每分钟落一份榜单、漏斗与候选快照（服务端主动抓取，不依赖页面打开），方便收盘后回看竞价阶段的真实状态。

竞价阶段的历史快照仍受服务启动时间限制：服务没运行、网络中断或上游限流时，对应分钟不会有快照；缺失就是缺失，不做补造。

## 刷新节奏

- 个股价格：交易时段 1 秒，非交易时段 15 秒；首页上证指数走同一条报价轮询。
- 上证指数分时：交易时段 3 秒，非交易时段 30 秒；后端分时缓存 2 秒，保留完整分钟点，折线以昨日收盘价作虚线基准，下方红绿柱为逐分钟成交量（收 ≥ 开红、否则绿），与折线共用同一时间轴。
- 量能对比：用沪深两市合计成交额（上证指数 + 深证成指，腾讯指数行情）对比上一有效交易日同一时点，同时显示今日总额、差额金额、差额百分比与昨日同期成交额；差额 ≥ +5% 记为放量、≤ -5% 记为缩量，其余为量平。腾讯多日分时缓存 10 分钟，避免每次刷新都拉多日数据；东财备用节点给深证指数返回的成交额明显偏小，因此不直接相加东财指数金额。
- 涨跌家数：使用东财涨跌分布（`getTopicZDFenBu`）汇总沪深两市全部正在交易的 A 股，卡片上标「两市」；这是全市场口径，不是上证指数单市场的涨跌家数。涨跌分布缓存 3 秒并随分时 3 秒轮询更新；接口异常时退回上证指数自带的涨跌家数并标注「沪市」，不会把单市场数字冒充全市场。
- 涨停封单金额：选票页每 1 秒随行情刷新，取腾讯五档买一价 × 买一量 × 100；只有最新价与买一价都贴在涨停价时才计算，炸板 / 开板后立即改为「已开板」，不保留旧封单。行情尚未回传或未请求封单时退回涨停池快照并标注「池快照」。东财备用节点给深市个股返回的现价可能滞后，封单请求统一以腾讯实时价为准。
- 榜单与情绪：交易时段 10 秒，非交易时段 60 秒。
- 竞价抓强：竞价时段每 1.5 秒；盘前每 10 秒；非竞价时段停止轮询，只保留准备池。
- 实时预警：竞价 9:15–9:30 与盘中 9:30–15:00 轮询（9:15–9:20 只取数不弹；午间冻结），竞价 / 集合竞价阶段每 3 秒、盘中每 5 秒一次；休市不扫描。页面在后台且未开启桌面通知时暂停；开启桌面通知后为浏览器尽力调度，不保证准时。
- 隔夜计划：交易时段每 30 秒预演；收盘后停止自动轮询，手动重算。
- 老龙头画像：磁盘缓存 6 小时；首次构建期间前端每 3 秒重试，最多 15 次。
- 页面切到后台自动暂停，回到前台立即补一次。
- 交易状态按北京时间判断：盘前、集合竞价、盘中、午间休市、已收盘、周末休市。

报价接口有 850ms 缓存，榜单接口有 8 秒缓存，当日板块 / 个股资金有 20 秒缓存；手动刷新会跳过后端榜单缓存强制重建。竞价阶段复用报价缓存，1.5 秒轮询足够拿到新的撮合快照。

## 准确率与验证

本项目不提供"胜率"或收益承诺，但复盘页的晋级概率现在有一层可复核的走样本外校准，而不是只靠手调权重：

- 校准对象：主板 00/60 涨停股（剔除 ST / 退市 / 双创 20cm），标签是次日连板数继续抬升。
- 方法：按日 walk-forward，前一日及以前训练、后一日检验；特征做标准化，L2 逻辑回归，特征包括首封时间、封流比、封成比、炸板次数、板位、流通盘、板块涨停家数、板块龙一与市场晋级率。
- 启用门槛：至少 5 个测试日、200 个测试样本、AUC ≥0.55、Brier 优于基准、Top10% 晋级率高于基准，且 2 板+ 子集同样有效；任一不满足，模型权重为 0，完全回到规则口径。
- 不确定性：AUC 用分层 bootstrap 估计 95% 区间并显示在面板里；2 板+ 子样本区间若跨过 0.5，模型权重从 45% 压回 30%，避免把噪声当成优势。
- 可成交性：一字 / 秒板（9:25–9:30 首封且 0 炸板）在"可成交"指标中单独剔除，避免用买不到的票刷高命中；晋级榜里也会标注"一字 / 秒板"，并移到"只看不接"面板；明日待选同样不接受一字 / 秒板。
- 推荐台账：复盘页「推荐复盘」只跟踪复盘明确给出的晋级榜 / 明日待选，按次日真实日线核对。触发口径按计划执行（首板竞价 +1%–4%，连板 +1%–3%），缺口 >5%/6% 或 < -2% 记未触发，不按事后最优价假设成交；盘中快照未在收盘后定稿的交易日不纳入统计。台账文件为 `.cache/rec-ledger.json`，只从功能上线开始积累，不补造历史。
- 当前限制：东方财富涨停池只能回溯约 15 个交易日，首次校准样本约 700 条、测试日约 9 天；样本仍薄，2 板+ 子样本只有几十条，AUC 区间可能横跨 0.5。风格切换、监管降温、流动性变化都可能让模型失效。指标在复盘页「晋级概率校准」面板实时展示，不写死为承诺。
- 竞价：公开数据源不提供长期完整的集合竞价历史快照，仍无法严谨回测"9:20 竞价强度 → 次日收益"。
- 画像：延续率是历史样本统计，未扣交易成本、滑点、无法成交与停牌，不等于策略胜率。
- 选股：分数用于横向比较与排除，不是收益预测；数据降级时会保守降级，而不是补齐假数据。

建议按以下方式自行做前向验证：

1. 每个交易日记录候选：日期、代码、板块、角色、画像分、竞价硬条件、是否执行；
2. 次日记录：开盘跳空、是否延续、收盘结果、止损是否触发；
3. 至少连续 20–60 个交易日，统计候选数、执行数、延续率、平均跳空、假信号比例、最大单笔亏损；
4. 与"同板块随机 3 板股"的基线对比；跑不赢基线，说明当前画像没有增量信息；
5. 情绪退潮、数据源连续降级、画像样本不足 20 个交易日时，暂停使用并复盘。

只有可重复的样本外验证，才配叫"准确率"。

## 已知限制

- 龙头判定基于"涨停池 + 板块梯队 + 资金"的公开数据，无法判断新闻真伪；题材催化必须人工核验并自行承担判断责任。
- 集合竞价没有权威、免费、长期的历史快照，因此竞价规则无法做严格回测；本项目的竞价评分只用于实时排除虚强、追高与孤军，不承诺胜率。
- 竞价“高置信”是更严格的规则层（三关 + 硬确认 + 基因 ≥70 + 涨幅 2%–7% + 竞价额 ≥ 昨日成交 3% + 预警分 ≥78 且无核按钮风险），作用是减少弱票进入推荐；它没有经过样本外准确率验证，观察池也始终只解释“为什么关注”，不等于推荐。
- 隔夜三强最多 3 只、按隔夜分排序，今日一字 / 秒板不参与；没有合格票就空仓，不会用低分票补位。三强只是条件单草稿，不保证次日上涨或成交，跳空与滑点仍会让计划失效。
- 老龙头画像存在幸存者偏差：只统计已经走出来的高标；上游涨停池约保留 15 个交易日，本机累积上限 120 日 / 600 条，样本量仍需时间。
- 分桶延续率在样本少于 3 条时不参与加权；即使样本足够，风格切换也可能让规律失效。
- 晋级校准只覆盖复盘页的 2 板+ 前排排序，不是全市场胜率模型；样本按 `date|code` 在 `.cache/promotion-calibration.json` 累积，最多 120 个交易日 / 12000 条。校准未扣交易成本、滑点与涨跌停无法成交，Top10% 命中也不等于账户收益。
- 推荐台账的“触发买点”是用次日日线开盘价近似竞价成交，未模拟盘口深度、排队与滑点；触发样本少于 5 只时页面明确提示不能当稳定胜率。台账只有功能上线后的真实记录，没有功能上线前的完整样本，不用截图或记忆回填。
- 校准模型是 10 个特征的线性逻辑回归，容量有限；若后续加入更多特征，必须重新做走样本外验证，不能直接沿用当前权重。
- 节点票、情绪适配、流通市值与连板高度是公开短线经验与通用量化因子的结构化，不是经过严格回测的最优参数；没有可验证的高准确率开源短线模型，调整权重会改变排序。
- 东方财富 `push2 / push2his` 的部分 CDN 节点在个别网络下会被重置；程序会自动切到同源 `push2test`，若仍失败则资金关显示未通过，不会用假数据补齐。
- 板块目录优先使用实时目录（约 496 个行业板块），实时目录失败时退回本地 `boards.json`。极少数行业名仍可能无精确对应，页面会显示"板块资金映射缺失"。
- 资金近似口径（今日 + 5 日为正）只作参考，**不会**让板块通过"资金连续流入"这一关；必须今日与昨日均为真实净流入。
- 涨停池在盘中会变化，首次封板时间、炸板次数等字段以接口返回为准；收盘后复盘更稳定。
- 不同数据源之间可能有几秒延迟，价格与榜单不完全同步是正常现象。
- 隔夜条件单不是自动交易：不会连接券商、不会代下单，跳空、滑点、停牌都可能让计划失效。
- 实时预警依赖页面保持打开与公开数据源可用；浏览器后台节流、网络中断、接口限流都会导致提醒延迟或漏报。桌面通知需要手动授权，且不是服务器推送，不保证送达。
- 预警覆盖竞价 9:20–9:30 与盘中 9:30–15:00 的未封板候选；竞价是撮合、盘中是连续竞价，挂单都不保证成交。催化未核验或板块三关未过的预警仍按观察处理，不解除观察纪律。
- 漏斗与快照只从功能上线后开始记录：此前的竞价时段无法补录，只能按当日公开行情事后近似还原（如开盘涨幅、所属板块昨日涨停家数），不能还原当时的竞价基因分与预警分。
- 竞价快照依赖服务进程持续运行；服务重启、休眠、断网或上游限流会造成分钟级空档，空档不会被补造。
- 推荐记录与出榜历史保存在当前浏览器的 `localStorage`；换浏览器、换设备、清理站点数据或手动清空记录后不会恢复。服务端的首次推荐时间只保留本次进程内，重启后以前端已存的时间为准。
- 本项目没有任何"历史回测胜率"背书，也不构成投资建议。
